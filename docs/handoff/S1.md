### Verdicts
- **Pin accuracy: good.** Every package-vc checkout's `git rev-parse HEAD` equals the requested SHA (13 checkouts in the archives-off runs, 6 in `archives`).
- **Q1 multi-directory load-path: good with a condition.**
  - magit: `lisp/` is picked up (heuristic or `:lisp-dir "lisp"`); `magit`, `magit-section` load, `magit-version` = v4.7.1.
  - evil-collection: works with no extra load-path. It loads `modes/<mode>/` by absolute path from `evil-collection-base-dir`; `evil-collection-require` for magit and dired, and `evil-collection-init '(magit dired)`, succeed.
  - evil-ghostel: works as a second package from the ghostel repo with `:lisp-dir "extensions/evil-ghostel"` (loads from `evil-ghostel/extensions/evil-ghostel/`).
  - **vertico, corfu: bad as-is.** package-vc supports a single `:lisp-dir`. `extensions/` is not on the load-path and gets no autoloads: `(require 'vertico-directory)` and `(require 'corfu-popupinfo)` fail, and `vertico-directory-enter` / `corfu-popupinfo-mode` are unbound. GNU ELPA's spec uses `:renames (("extensions/" ""))`, which package-vc ignores. `vertico-unobtrusive` also fails to byte-compile (it requires `vertico-flat`, not on the load-path).
  - Condition: Doom adds `extensions/` to the load-path and generates autoloads for it itself. Verified: after `loaddefs-generate` on `extensions/` and adding it to the load-path, both commands are bound and `vertico-directory`, `corfu-popupinfo`, `vertico-unobtrusive` all load.
- **Q2 ghostel native module: download works; compile untested.**
  - package-vc builds nothing (`package-vc-allow-build-commands` is nil, and our spec has no `:make`). The module comes from ghostel's own code.
  - Download: `ghostel--download-module` fetched `releases/download/v0.60.0/ghostel-module-x86_64-linux.so`. It requests `ghostel--minimum-module-version` (0.60.0, the pin's version), not "latest". `module-load` succeeds; `ghostel--module-version` = 0.60.0. `ghostel--resource-root` resolves to the checkout root in the `lisp/` layout.
  - The module lands in the package dir, so a reinstall deletes it. P11 should set `ghostel-module-directory` outside the package tree.
  - Compile (`zig build`): **untested.** zig is not installed; `build.zig.zon` needs zig >= 0.17.0.
  - Live baseline: no `ghostel-module*` file exists anywhere under `~` or `/opt/minh`, so the live install has no module today.
- **Q3 unpinned dependencies: bad as asked; good with conditions.**
  - With archives on, every dep not already installed via package-vc comes from an archive at its newest version, unpinned. The `archives` run installed only the six targets, and pulled from MELPA: evil 20260728.1438, goto-chg 20240407.1110, llama 20261001.1538, cond-let 20261001.1537, with-editor 20261109.2119, magit-section 20261107.2107. Source: `package-vc-install-dependencies` → `package-install-from-archive`.
  - Built-ins satisfy some deps silently: Emacs 31.1's transient 0.13.3 meets magit's `>= 0.13`, so in the `archives` run magit ran against the built-in transient, not the 0.13.8 that straight has. compat (31.1.9999) and seq (2.24) are also satisfied by built-ins.
  - Today's straight setup is only partly pinned too: doom+ pins transient and cond-let as an exception (`tools/magit/packages.el`), and magit-section shares magit's repo, but with-editor, llama and goto-chg have no `package!` and are unpinned today.
  - With archives off (`package-archives` nil) and every dep declared at a pin: nothing comes from an archive, all packages land at their pins, and the package-vc transient shadows the built-in one. Two conditions apply:
    - **Self-dependency bug, must work around.** package-vc reads `Package-Requires` from every `.el` in the lisp dir. When a sibling file requires the package itself, that entry is dropped from `missing` but kept in the generated `-pkg.el`. `package-activate-1` then recurses → `excessive-lisp-nesting`, and that package and everything depending on it fails to activate. Hit by evil (`evil-test-helpers.el` requires evil) and by magit-section installed from the magit repo (`magit.el` requires magit-section). In `pinned`/`reversed`, magit, evil, evil-collection and evil-ghostel were all unloadable. Fix (verified in `fixed`): `:ignored-files`, as GNU/NonGNU `elpa-packages` already does. evil: `("evil-test-helpers.el")`; magit-section: `("lisp/magit.el")`; ELPA's magit spec also ignores `lisp/magit-section.el`. Doom's recipe translation must carry these.
    - **Order: must sort topologically.** A package installed before its deps cannot activate (`Unable to activate package 'magit'. Required package 'cond-let-1.1' is unavailable`), and package-vc then skips byte-compilation for it, silently. In `fixed-reversed`, magit, evil, evil-collection and evil-ghostel have 0 `.elc` files; they still load from `.el` in a fresh process once the deps are present, but run uncompiled. With archives on, a dep installed after its dependent comes from the archive instead.
    - **Archives must be off** (`package-archives` nil) during `doom sync`, not just as an alternative to sorting: in the `archives` run the caller's spec was not saved (no `package-vc-selected-packages` save logged) and evil-ghostel's `:lisp-dir` was dropped (see Unexplained).
  - Spec persistence: in batch, package-vc saves the spec only "temporarily" (`package-vc-selected-packages` via customize). Activation in a fresh process still works, because the autoload indirection to `:lisp-dir` is written at install time. A later `package-vc-upgrade` or rebuild would lose `:lisp-dir` / `:ignored-files` unless Doom supplies the specs again.
  - Unexplained: in the `archives` run, evil-ghostel's `:lisp-dir` was ignored (its autoloads point at `lisp/`, and `(require 'evil-ghostel)` fails); in the archives-off runs it was honoured. Cause not verified.

### Is the fallback triggered?
Under the plan's rule ("if any answer is bad, use the fallback"), yes: Q1 is bad for vertico/corfu and Q3 is bad as asked. Every bad answer has a workaround verified in `fixed`, though, so the user should choose:
- **A. Fallback** (clone at pin, add to load-path, generate autoloads, no package.el). Recommended. To be safe, package-vc already needs Doom to compute extra load-path dirs and autoloads, declare every transitive dep, turn archives off, carry per-package `:ignored-files`, and re-supply specs. What package-vc still adds is byte-compilation and `-pkg.el` metadata, and its failure modes (activation recursion that takes dependents down with it, silently skipped byte-compilation) are worse than a plain backend's.
- **B. package-vc with conditions:** archives off; every transitive dep declared with a pin; install in topological order; `:ignored-files` per package where needed; Doom adds `extensions/`-style dirs and their autoloads; specs re-supplied on every sync. Cost: magit-section becomes a second full clone of the magit repo, with both `lisp/` dirs on the load-path (same for ghostel/evil-ghostel).
Either way, P11 must add pins for the deps that are unpinned today (with-editor, llama, goto-chg seen here, plus the deps of the other packages, which S1 did not enumerate).

### Decision
- 2026-11-12, user: **A, the fallback backend** (clone at pin, add to load-path, generate autoloads, no package.el). P11 is planned on that basis; the B notes stay as background on why.
